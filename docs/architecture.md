## 当前实现与未知项

SAT 练习状态和历史记录保存在浏览器 IndexedDB / localStorage，判分由客户端完成。当前没有登录、按账号隔离或云端答题记录，已接入 SAT 数学，但仍没有官方量尺分或自适应考试实现。新的统一首页保留原型答题引擎，并新增统一本机服务和公共题库 JSON；尚未新增云端数据库或账号权限。

初次源码接入未导入真实资源。统一首页任务已授权将题库与必要图片迁移到被 Git 忽略的 `local-data/`；旧个人记录与题目中夹带的已选答案不迁移。OCR 功能已取消，上传界面、任务处理代码和服务 API 已移除；仓库不包含 OCR 环境、模型或依赖，也不再创建 OCR 输出目录。题目仅使用 JSON 导入。Git 中仍只保存空题库种子与两道原创合成题；本机可独立加载授权迁移的真实题库。此清理减少了原型的外部运行依赖，不改变未来统一身份与记录接口的边界。

托福源码已接入，本地整合版本采用 `toefl` 分支 `98aa9c7`，统一服务仅提供原创匿名构建；原云端账号、录音和 AI 源码保留，但未启用正式服务。统一首页采用原生 HTML/CSS/JavaScript 和 Python 标准库本机服务；正式身份服务、云端存储与部署平台仍待确定。TOEFL URL 页面入口由模块原生协议处理，公共桥接只隔离存储与录音库，避免覆盖新版导航。具体接口问题与验证见 [本地整合报告](local-integration-2026-10-23.md)。

## 整合顺序

### 1. 收集并复现原有功能

SAT 已先导入可独立运行的纯代码版本；继续核实所需题库资源、原有行为与验证范围，并收集托福源码和配置说明。记录原始提交版本或导出清单，先分别复现，再决定统一运行方案。参考 [源码接入清单](source-intake.md)。

### 2. 统一入口

目标是同一站点下提供考试入口，例如 `/sat` 和 `/toefl`。根据源码情况，可以整合为一个应用，也可以先保留模块内部实现，通过统一入口与路由接入。

当前 `/` 为统一首页，`/sat/` 接入 SAT 引擎，`/toefl/` 接入托福匿名预览；AP 与跨考试 Personal Vocab 保留接口。两个考试使用新平台独立浏览器存储名称，避免读取原应用的个人记录。启动与接口见 [统一首页](unified-home.md)，公共兼容格式见 [题库格式](question-format.md)。统一登录与数据库尚未实现。

### 3. 统一身份与记录

登录由公共身份层提供。SAT 与托福模块使用相同的用户标识，按公共记录约定保存答题结果。后端检查当前用户身份，限制记录访问范围。

### 4. 部署与验收

设置独立的测试环境与正式环境；提供正式网址和测试网址。验证校内网络访问、跨设备登录、记录保存恢复和账号间权限隔离。再按实际请求量和资源使用判断免费额度是否足够。

## 逻辑模块边界

| 模块 | 职责 |
| --- | --- |
| 公共入口 | 首页、导航、考试入口 |
| 身份与账号 | 登录状态、用户标识、学生与管理员角色 |
| SAT | SAT 题目展示、计时、作答和考试特有逻辑 |
| 托福 | 托福题目展示、计时、作答和考试特有逻辑 |
| 答题记录 | 保存作答、恢复进度、查询历史、提交完成状态 |
| 题库管理 | 导入、校验、版本标识和资源引用 |

`front-end/web/` 实现公共首页，`front-end/sat/` 保留 SAT 引擎，`back-end/shared/question_schema.py` 定义题库规范与适配，`back-end/server/serve_platform.py` 提供本机路由。身份与云端记录仍是目标职责。

## 公共数据约定草案

- 用户使用稳定的内部 ID；不依赖邮箱字符串作为永久关联主键。
- 题目带有考试类型与来源标识，防止两个题库的原始 ID 冲突。
- 一次练习或考试具有独立 attempt ID，并明确进行中、已提交等状态。
- 记录关联题目版本；题目修改后，历史作答仍可解释。
- 保存接口支持重复提交或网络重试，避免生成重复记录。
- 统一使用 UTC 存储时间，再按界面需要转换显示。
- 学生只能读写自己的记录；管理功能需要独立权限检查。
- 对有服务端评分要求的题型，由服务端计算或校验结果，不直接信任浏览器提交的分数。

这些约定将在检查两套原始数据模型后确认并更新，当前不是已执行的数据库结构。SAT 现有浏览器记录不能直接视为公共记录接口；后续需要确定用户关联、题目版本和保存恢复方式，并验证账号间权限隔离。
