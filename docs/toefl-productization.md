# 托福模块接入与产品化计划

记录日期：2026-10-21。关联任务：[Issue 1](https://github.com/XcommandX/school-exam-platform/issues/1)。

面向约 150 名总用户的校内 SAT / 托福平台，先接入可独立运行的托福模块，再整合公共入口、身份与学习记录。保留原有练习行为和用户数据，避免在源码接入时同时全面重写。

本仓库尚未导入应用。下文中的现状来自原开发环境的初步只读检查；目录、公共接口、权限层级和部署方式属于待团队审查的方案，不能当作已经实现的功能。容量预算见 [服务器配置与容量估算](server-sizing.md)。

## 已确认需求与现有基础

| 项目 | 状态 |
| --- | --- |
| 校内平台 | 约 150 名总用户，统一网址、统一登录、云端答题记录；峰值并发待确认 |
| 团队 | 约三位开发者，在 Windows / macOS 上通过功能分支与 PR 协作 |
| 托福原系统 | 已有阅读、听力、口语、写作练习，以及词汇、复习、进度统计、录音和 AI 练习估分 |
| 原系统运行方式 | 浏览器 HTML / CSS / JavaScript；后端使用 Cloudflare Worker、D1 和 Workers AI；Python 脚本构建资源 |
| 原系统身份 | 多账号、服务端会话、单次邀请注册；账号与作答按用户隔离 |
| 原系统保护 | 题库资源、作答及录音采用加密保护，访问资源与 API 前校验登录；敏感配置使用服务端 Secret |
| 管理员查看范围 | 当前约定为学习统计、逐题分数、词汇进度；不扩大为原始作文、转写或录音 |
| SAT | 源码、运行环境、资源格式、身份及存储方式尚待检查 |
| 本仓库 | 仅有协作基础与文档，没有可运行的应用或已接入的数据库 |

原系统的“管理员”是该托福站的角色，不代表已经取得未来平台的全局管理权。GitHub 写入权限、网站数据管理权限和云服务部署权限分别管理。

## 统一入口与模块边界

用户在统一入口登录后，进入 `/toefl`、`/sat` 或后续考试模块。Git 分支用于短期开发任务；考试模块通过目录、路由和接口长期维护。

建议先采用同一仓库中的独立模块，公共能力在确有复用需求后抽取。候选结构如下，源码接入 PR 应根据实际依赖确认后再创建：

```text
apps/
  portal/       统一首页与入口
  toefl/        托福界面与考试业务
  sat/          SAT 界面与考试业务
packages/       已确定的公共代码与接口约定
docs/           接入、架构、容量、权限和运维说明
```

模块可暂时保留自己的内部实现，不要求立刻统一前端框架。先检查 SAT 源码，再决定是同一应用部署，还是统一入口下分别运行后端。若采用同一 Cloudflare 账号中的多个 Worker，可评估内部 Service bindings；它支持内部服务调用和独立部署，但用户身份仍需明确传递和校验。参见 [Cloudflare Service bindings](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/)。

同一路径域名会共享浏览器安全边界。`/toefl` 与 `/sat` 路径不是彼此的安全隔离区；各模块都需要审查脚本与内容注入风险。如果需要更强的浏览器隔离，应另行评估子域名与单点登录，不能只依赖目录划分。

接入适配需要核对：

- 页面基础路径、直接打开子页面、刷新、浏览器返回、资源相对路径。
- 公共账号接口与考试接口命名空间，例如 `/api/auth`、`/api/toefl`、`/api/sat`；这些名称尚未冻结。
- Cookie 名称与范围、登录及退出行为；不让某一模块清理其他模块未同步的草稿。
- localStorage、IndexedDB、缓存及 Service Worker 的模块命名空间、账号范围和生命周期。
- 从公共入口进入口语时的麦克风授权、题目播放、录音恢复与保存流程。

## 公共身份与学习记录

公共身份层提供稳定的内部用户 ID。模块后端从服务端验证过的会话或受信任调用上下文取得身份，不能相信浏览器自行提供的用户 ID 或角色。

建议区分平台管理员、模块管理员和学生，具体授权表在身份接入 PR 中确认。每个 API、录音和受保护题库资源都校验权限；学生仅访问自己的私人记录。管理员默认只能查看明确授权的统计范围。参见 [OWASP 访问控制建议](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

账号接入应提供旧用户 ID 与新用户 ID 的映射方案，不因用户名相同就合并账号。是否迁移历史账号、密码验证信息和学习记录由团队与数据负责人确认；禁止重置、清空或覆盖现有数据来完成整合。

答题记录沿用 [架构文档中的公共数据约定草案](architecture.md#公共数据约定草案)：考试类型、来源题目 ID、题目版本、独立 attempt ID、UTC 时间、幂等保存、权限检查。先通过适配层连接旧数据，再逐步调整内部模型。

## 产品化前的重点改造

| 范围 | 现状或风险 | 接入与验收要求 |
| --- | --- | --- |
| 构建可移植性 | 原构建脚本包含开发电脑绝对路径；部分维护中的前端文件放在 `dist` 目录 | 识别真正源码与生成产物，改用项目相对路径；避免被 `.gitignore` 漏掉；记录依赖和锁文件，分别验证 Windows / macOS |
| 密码与会话 | 原实现使用带盐 PBKDF2-HMAC-SHA256、100,000 次迭代 | 评估统一身份服务或升级方案；OWASP 当前建议该算法 600,000 次；验证选定运行时兼容性、CPU 成本及旧哈希升级流程，保留安全 Cookie 与可撤销会话 |
| 登录限流 | 原登录失败限制主要按 IP；校园出口可能多人共用 | 结合账号、IP 与退避策略限制尝试，避免一人输错使整校用户被统一限制；验证并发和绕过情况 |
| 前端内容安全 | 原内容安全策略允许内联脚本；同源模块可互相影响 | 接入时审查题目、作文、AI 输出等内容的渲染和转义，评估去除内联脚本或采用 nonce / hash；不因整合放宽访问保护 |
| AI 评分 | 已有缓存、重复请求合并及错误反馈；暂无面向全校的完整预算控制 | 增加服务端每用户配额、全局预算、并发上限、排队与失败重试；多实例控制不能只依赖进程内 Map；模型密钥仅在服务端 |
| 录音存储 | 原录音保存在 D1，存在单文件限制与总量增长 | 评估私有对象存储，校验大小、格式和归属；数据库保存索引；制定保留、删除、备份与恢复规则；迁移前后核对文件摘要 |
| 数据同步 | 原记录按账号和版本同步，部分数据以整块 JSON 保存 | 保留冲突处理和录音保存；评估增量记录、查询索引和分页，避免数据随历史增长后全量传输；验证两设备同时修改 |
| 成绩可信度 | 部分客观题结果由浏览器计算后随状态上传 | 个人练习可即时反馈；如用于班级评价或排行榜，服务端应根据题目版本重新计算或校验成绩，不信任上传分数 |
| 管理与维护 | 现有保护主要服务于私人站点 | 为角色变更、邀请、账号管理等记录不含敏感正文的操作日志；增加必要的会话撤销与受控账号恢复流程，管理入口考虑二次验证 |
| 运行保障 | 新平台尚未部署 | 分离测试与正式的数据库、密钥和资源；设置错误、容量与额度告警；验证备份恢复和发布回滚 |

密码升级依据：[OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。这些是接入任务的验收方向，不表示本次已完成安全审计或整改。

AI 口语评分目前主要基于转写内容，不能据此声称已评价真实发音和声学流利度。平台继续标明练习估分与评价范围；选用新的处理方前确认作文和录音的数据处理方式，不能在后台无提示改用其他供应商。

## 源码与资源的提交范围

| 内容 | 管理方式 |
| --- | --- |
| 源码、测试、脚本、锁文件、配置样例 | 进入 Git，保留来源版本和说明 |
| 数据库结构与迁移 | 进入 Git，提供匿名数据；注明执行顺序、恢复方式和兼容性 |
| 题库、大量图片与音频 | 优先通过受控资源存储分发，Git 保存格式、版本清单和校验摘要；本地开发提供可运行的匿名小样本 |
| Secret、内容加密密钥和部署凭据 | 使用专用密钥管理与环境配置，不进入 Git、压缩包或日志 |
| 学生信息、密码哈希、作答、作文、录音和数据库导出 | 留在受控数据系统，不随源码提交；备份单独授权、加密和保管 |
| `dist` 等生成产物、本地云工具状态 | 默认不提交；先把实际维护源码迁出生成目录，防止误删或漏交 |

保持仓库私有。源码私有并不自动保护部署网址；静态资源和对象存储仍需访问控制。题库和音频接入时记录来源、使用授权范围及其是否覆盖校内多用户场景。

当前资源采用 AES-GCM；资源发布、状态解密和历史录音读取依赖正确密钥。整合时不能因本地缺少密钥而自动生成新密钥并替换正式配置。新环境使用新密钥，旧数据迁移采用显式版本和验证流程；如需轮换，保留受控恢复路径。已授权用户可以保存其已接收到的内容，不能把加密表述为任何条件下都无法提取。

## 分阶段任务与验收

1. **盘点与导入**：按 [源码接入清单](source-intake.md) 核实来源、依赖、资源和现有行为；独立分支导入托福源码和匿名样本，补充真实启动与检查命令。不连接正式数据执行开发测试。
2. **跨平台复现**：Windows 与 macOS 分别验证进入题目、作答、提交、解析、录音和离线恢复；记录执行者、环境和结果，未验证的平台明确留待验证。
3. **公共入口与身份适配**：确认 SAT 情况和公共接口；验证一次登录进入两模块、退出及切换账号、刷新与返回，以及 API 和音频的跨账号拒绝访问。
4. **数据与资源迁移试演**：使用匿名副本演练 ID 映射、幂等重跑、版本兼容和恢复；正式迁移单独安排，先备份、再核对、不清空原站。
5. **容量与发布**：按 [容量验证计划](server-sizing.md#容量验证与扩容条件) 压测测试环境；PR 审查、预览验收、合并后发布。记录版本、执行步骤、回滚范围及数据恢复方式。

每阶段在 Issue 中明确负责人和验收条件。跨模块接口修改在 PR 中说明影响，由对应模块负责人共同检查。团队决定、接口和验证证据都写入仓库文档；具体人员分工尚待约定。

## 本次文档任务的边界与下一步

本次仅记录初步盘点、接入方案和配置预算，不导入应用、不选定付费供应商、不执行数据库迁移、不改变现有账号、作答或录音，也不部署正式服务。

下一项建议任务是“导入可独立运行的托福模块及匿名测试样本”。开始前确认两位模块负责人的范围、SAT 源码位置、旧数据迁移意向，以及全校峰值并发和录音保留需求。新增持续费用须先在部署评估与任务中列明。
